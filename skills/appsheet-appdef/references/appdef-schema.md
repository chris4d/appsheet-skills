# AppSheet appdef field reference

Observed against `PlatformVersion: 5.1` exports. AppSheet adds fields over time;
treat unknown keys as optional and never fail on them.

## Top level

```json
{
  "Id": "guid",
  "ShortName": "Example App",
  "Name": "ExampleApp-123456789",
  "Version": "1.000209",
  "PlatformVersion": 5.1,
  "LastModified": "2026-11-06T17:44:20.7060487Z",
  "Status": "Ready",
  "IsRunnable": true,
  "IsValid": true,
  "UserRoles": [ { "Name": "User", "IsDefaultRole": true }, { "Name": "Admin" } ],
  "Behavior": { "...": "..." },
  "Presentation": { "Controls": [], "FormatRules": [] },
  "AppData": {
    "DataSets": [],
    "TableSlices": [],
    "DataSchemas": [],
    "DataActions": [],
    "ExpressionSettings": {}
  }
}
```

## DataSets (tables)

| Field | Meaning |
|---|---|
| `Name` | Table name shown in the editor |
| `SchemaName` | Key into `DataSchemas` (usually `<Name>_Schema`) |
| `ProviderName` | `google_tables` (AppSheet database), `google` (Sheets), `native`, `sqlserver`, etc. |
| `SourcePath` | Database / spreadsheet name |
| `SourceQualifier` | Sheet/tab name or table qualifier |
| `Source` | Provider-specific id (`ID=base/.../tables/...`, `DocId=...`) |
| `UpdateMode` | Numeric mode; `7` when `UpdateModeExpression` is used |
| `UpdateModeExpression` | Who may add/edit/delete, e.g. `=IF(..., "ALL_CHANGES", "READ_ONLY")` |
| `DataFilter` | Security filter (row visibility), e.g. `=LOOKUP(USEREMAIL(), "Users", "Email", "ActiveFlag") = "Yes"` |
| `DataAccessMode` | `as app creator` or `as app user` |
| `IsShared` | Shared data source flag |
| `ColumnOrder` | Usually just `["_RowNumber"]`; real order is in the schema |

`AllowedUpdates` is a bitmask and is not a reliable substitute for
`UpdateModeExpression`. Read the expression.

## DataSchemas (columns)

One schema per table. `Attributes[]` is the authoritative column list and order.

| Field | Meaning |
|---|---|
| `Name` | Column name |
| `Type` | `Text`, `Number`, `Decimal`, `Price`, `Yes/No`, `Date`, `DateTime`, `Enum`, `EnumList`, `Ref`, `Image`, `File`, `Url`, `LongText`, `List`, `Show`, etc. |
| `TypeAuxData` | **JSON string** with type options and all conditional expressions |
| `IsKey`, `IsKeyPart` | Key column |
| `IsLabel` | Row label column |
| `IsVirtual` | Virtual column |
| `IsRequired` | Required |
| `IsReadOnly` | Read-only |
| `IsHidden` | Hidden |
| `Searchable` | Searchable |
| `IsScannable`, `IsNfcScannable` | Barcode / NFC |
| `IsSensitive` | PII |
| `AppFormula` | App formula, with leading `=` |
| `Formula` | Spreadsheet formula (Sheets-backed columns) |
| `Default` | Initial value, e.g. `UNIQUEID()`, `onlyvalue` |
| `DefaultExpression.SourceExpr` | Parsed initial value when `Default` is absent |
| `DisplayName`, `Description` | User-facing text |
| `ResetOnEdit` | Reset on edit |
| `IsSys`, `IsAutoGenerated` | System / generated column |
| `InternalQualifier` | Compiled expression AST and column stats; ignore for analysis |

### TypeAuxData keys

Common to all types:

```
Show_If, Editable_If, Required_If, Reset_If,
Valid_If, Error_Message_If_Invalid, Suggested_Values
```

Text: `MaxLength`, `MinLength`, `LongTextFormatting`, `IsMulticolumnKey`.
Number/Decimal/Price: `MaxValue`, `MinValue`, `StepValue`, `NumericDigits`,
`ShowThousandsSeparator`, `NumberDisplayMode`.
Yes/No: `YesLabel`, `NoLabel`.
Enum/EnumList: `EnumValues`, `AllowOtherValues`, `AutoCompleteOtherValues`,
`BaseType`, `BaseTypeQualifier`, `EnumInputMode`.
Ref: `ReferencedTableName`, `ReferencedRootTableName`, `ReferencedKeyColumn`,
`ReferencedType`, `ReferencedTypeQualifier`, `IsAPartOf`, `InputMode`,
`RelationshipName`. `ReferencedKeyColumn` names the target column whose value is
stored in the Ref cell; it should be the target's `IsKey` column. AppSheet
database tables also carry an auto, undeletable `Row ID`; semantic keys coexist
with it (see `appsheet-patterns/references/schema-conventions.md`).

Ref columns often also carry `IsAPartOf` in `TypeAuxData`; if true, child rows
are treated as line items of the parent.

## TableSlices

| Field | Meaning |
|---|---|
| `Name` | Slice name |
| `SourceTable` | Underlying table |
| `FilterCondition` | Row filter, leading `=` (primary location) |
| `RowFilterCondition` | Usually null in current exports |
| `FilterExpression.Expression` | Usually empty; `FilterExpression.Description.Content` mirrors the filter |
| `FilterEvaluatable` | Compiled AST |
| `Columns` | Columns exposed by the slice |
| `UpdateMode`, `UpdateModeExpression` | Slice-level update override |

A slice inherits the table's security filter. A slice filter is a *view filter*,
not a security boundary.

## DataActions

| Field | Meaning |
|---|---|
| `Name` | Action name (may repeat across tables) |
| `Table` | Target table |
| `ActionType` | `SET_COLUMN_VALUE`, `ADD_RECORD`, `DELETE_RECORD`, `EDIT_RECORD`, `NAVIGATE_APP`, `NAVIGATE_URL`, `EMAIL`, `CALL`, `SMS`, `OPEN_FILE`, `EXPORT_VIEW`, `IMPORT_FILE`, `EXECUTE_ACTION`, `GROUPED`, ... |
| `Condition` | “Only if this condition is true”, leading `=` |
| `ColumnToEdit`, `Value` | Single-column set-value shorthand |
| `Icon` | Font Awesome class, e.g. `fas fa-check` |
| `ActionOrder` | Order within a grouped action |
| `ActionSettings` | **JSON string** with display and behavior settings |
| `ActionDefinition` | Typed object; preferred when present |
| `IsEmbedded` | Embedded/system action |

`ActionDefinition` keys worth reading:

```
Assignments: [{ ColumnToEdit, NewColumnValue }]   # SET_COLUMN_VALUE
NavigateTarget: "=LINKTOFORM(...)"                # NAVIGATE_APP
Prominence: "Display_Prominently" | "Display_Overlay" | "Display_Inline" | "Do_Not_Display"
NeedsConfirmation, ConfirmationMessage, BulkApplicable, ModifiesData
InputParametersUsed
```

For `SET_COLUMN_VALUE`, `Assignments` is the full list. The top-level
`ColumnToEdit` / `Value` only describe the first assignment.

## Presentation.Controls (views)

| Field | Meaning |
|---|---|
| `Name` | Unique view name |
| `DisplayName` | Optional override |
| `TableOrFolderName` | Table **or slice** that supplies the data |
| `Action` | View type: `table`, `card`, `gallery`, `detail`, `form`, `deck`, `dashboard`, `map`, `chart`, `calendar`, `onboarding` |
| `Position` | `first`, `next`, `middle`, `later`, `last`, `menu`, `ref`, `left`, `center`, `left most` |
| `ShowIf` | Show-if expression, leading `=` |
| `Parameters` | Usually sort/group column names shown in the summary |
| `Settings` | **JSON string** copy of the view settings |
| `ViewDefinition` | Typed view settings; preferred |
| `_isSystemGenerated` | Auto-created ref/detail/form view (annotation) |

`ViewDefinition` keys by type:

- Table: `ColumnOrder`, `ColumnWidth`, `EnableQuickEdit`, `GroupBy`, `SortBy`,
  `GroupAggregate`, `PrimarySortColumn`, `IsPrimarySortDescending`, `Events`,
  `Icon`, `MenuOrder`.
- Card/Gallery/Deck: `MainDeckImageColumn`, `ImageShape`,
  `PrimaryDeckHeaderColumn`, `SecondaryDeckHeaderColumn`, `DeckSummaryColumn`,
  `ShowActionBar`, `ActionColumns`, `GroupBy`, `SortBy`, `Events`, `Icon`.
- Detail: `ColumnOrder`, `HeaderColumn`, `Events`, `Icon`.
- Form: `ColumnOrder`, `Events`, `Icon`, `FormStyle`.
- Dashboard: `ViewEntries[]` with `ViewName`, plus `Icon`.
- Map/Chart/Calendar: type-specific config plus `SortBy`/`GroupBy`.

`GroupBy` and `SortBy` entries are `{ "Column": "...", "Order": "Ascending" }`.
`Events` entries look like `{ "EventType": "Row Selected", "EventAction": "**auto**" }`.

## Presentation.FormatRules

Each rule normally carries a name, a table, a condition, and a format object.
Format rules are often empty in exports; if present, treat unknown keys as
optional and report the condition + columns rather than trying to interpret every
style field.

## Behavior (auth, bots, offline)

| Field | Meaning |
|---|---|
| `AuthRequired` | Require sign-in |
| `AllowAllSignedInUsers` | Any Google account may use the app |
| `DomainAuthRequired`, `AuthDomain` | Domain restriction |
| `AuthProvider` | e.g. `google` |
| `Offline`, `LaunchOffline`, `FullOfflineCaching`, `DeltaSync` | Sync/offline behavior |
| `AppBots` | Automation bots |
| `AppProcesses` | Processes used by bots |
| `WorkflowRules` | Legacy workflow rules (often null) |

Bots are the most version-variable area. When reporting them, summarize name,
event, table, condition, and steps; do not assume a fixed schema.

## Writing a custom query

```python
import json

d = json.load(open("appdef.json", encoding="utf-8-sig"))
app = d["AppData"]

tables = {t["Name"]: t for t in app["DataSets"]}
schemas = {s["Name"]: s for s in app["DataSchemas"]}

def columns(table):
    ds = tables[table]
    return schemas[ds["SchemaName"]]["Attributes"]

def aux(col):
    return json.loads(col.get("TypeAuxData") or "{}")

for col in columns("Materials"):
    a = aux(col)
    if a.get("Show_If"):
        print(col["Name"], a["Show_If"])
```

Views require the other tree:

```python
for view in d["Presentation"]["Controls"]:
    print(view["Name"], view.get("Action"), view.get("TableOrFolderName"))
```
